# TCG Stock Watch → Gallant Peak Web Integration Design

Date: 2026-10-22
Status: Proposed for review
Repositories: `galla-bit/gallant-peak-tcg-hunt`, `galla-bit/gallant-peak-web`

## Purpose

Integrate the existing Gallant Peak × TCG Hunt stock-watch capability into the public Gallant Peak website without moving collector logic, credentials, raw observations, Discord configuration, or trusted/admin state into the static GitHub Pages application.

The public website is a presentation surface. TCG Hunt remains the owner of collection, verification, normalization, and publication eligibility.

## Success criteria

1. Existing stock-watch and Discord/app paths continue independently.
2. Gallant Peak Web can render genuine delayed NZ retail availability from TCG Hunt.
3. Demo/fabricated stock cannot be mistaken for observed availability.
4. No collector credentials, internal watch configuration, raw retailer responses, admin state, or private diagnostics are exposed to the browser.
5. Invalid, stale, unavailable, or schema-incompatible data fails closed in the UI.
6. The first transport is simple enough for the current static GitHub Pages deployment but can later be replaced by a public API without redesigning the UI data model.
7. Future approved supplier/retailer inventory feeds can enter the TCG Hunt normalization pipeline rather than creating a separate website inventory system.

## Current boundaries

`gallant-peak-web` is a static React/Vite application deployed through GitHub Pages. Its current `/tcg-hunt` route is presentation-only and explicitly says its data connection is not live.

`gallant-peak-tcg-hunt` contains the monitoring system and existing bridge/security machinery, including `bridge_http.py` and `bridge_inventory.py`. Existing fail-closed controls must not be weakened to make the web integration easier.

The website must never communicate directly with retailer collectors or trusted bridge/admin interfaces.

## Architecture

```text
Retailer monitors                  Future approved supplier feeds
        |                                      |
        +------------------+-------------------+
                           v
                 TCG Hunt ingestion
                           |
                           v
              normalization / verification
                           |
                           v
                 publication policy
                           |
                           v
              public-safe delayed snapshot
                           |
                           v
             Gallant Peak Web /tcg-hunt

Existing private outputs (Discord/app/admin) remain separate consumers.
```

### Ownership

TCG Hunt owns:
- source collection;
- source identity and retailer mapping;
- normalization;
- observation timestamps;
- stock/availability interpretation;
- publication eligibility;
- delay/staleness policy;
- public snapshot generation;
- removal of private/internal fields.

Gallant Peak Web owns:
- fetching the public artifact;
- validating the public schema again at the browser boundary;
- rendering filters, states, timestamps, prices and retailer links;
- accessible loading, empty, stale and failure states;
- never upgrading an unknown state into an in-stock claim.

## Phase-one transport

Use a versioned public JSON snapshot rather than introducing a permanent application server solely for the website.

The snapshot is generated by TCG Hunt from already-normalized observations after publication-policy checks. It is published to an explicitly public location that GitHub Pages can fetch over HTTPS.

The website must not fetch repository internals, raw collector output, Discord payloads, logs, staging artifacts or trusted bridge endpoints.

The transport location is deployment configuration, not a hard-coded secret. The URL is public by definition and may be supplied through a Vite public environment variable or equivalent build-time configuration.

A future HTTP API may replace the JSON artifact as long as it implements the same public contract or a deliberately versioned successor.

## Public data contract

Initial schema, conceptually:

```json
{
  "schema_version": 1,
  "generated_at": "2026-10-22T00:00:00Z",
  "delayed": true,
  "items": [
    {
      "id": "opaque-public-id",
      "game": "Pokemon",
      "product": "Example product",
      "retailer": "Example retailer",
      "price_nzd": "189.99",
      "availability": "in_stock",
      "observed_at": "2026-10-21T23:45:00Z",
      "retailer_url": "https://retailer.example/product"
    }
  ]
}
```

Allowed availability values for v1:
- `in_stock`
- `limited`
- `out_of_stock`
- `unknown`

The website must treat missing/unrecognized values as `unknown`, never `in_stock`.

`price_nzd` is a decimal string to avoid binary floating-point ambiguity in the contract. Missing price is allowed and displayed as unavailable rather than inferred.

`id` is an opaque public identifier. It must not expose internal database keys, credentials, watch IDs, source hashes, or security identifiers.

## Explicitly prohibited public fields

The snapshot must not contain:
- credentials, tokens, cookies or authorization material;
- Discord webhook/channel configuration;
- internal watch IDs or allowlists;
- raw HTML or full source responses;
- internal source hashes/digests used by trusted controls;
- scheduler/admin state;
- private retailer notes;
- unpublished supplier commercial terms;
- customer data;
- internal audit/security logs;
- trusted bridge manifests or approval state.

The public schema should be allowlist-built, not created by serializing an internal object and deleting known-sensitive keys.

## Delay and freshness

The public surface remains deliberately delayed from internal monitoring. The exact delay is TCG Hunt configuration and should not be represented as real-time unless that policy is intentionally changed later.

The artifact contains `generated_at`; each item contains `observed_at`.

The website calculates presentation freshness but does not alter stock interpretation. If the artifact exceeds the configured maximum age, the UI enters a stale state and stops presenting availability as current. It may show the last observation with an explicit stale/unavailable warning only if the product decision approves that presentation; safest v1 behavior is to suppress stock cards and show radar unavailable/stale.

## Web UX

`/#/tcg-hunt` evolves from the current static panel to:

- project explanation: legitimate NZ retail stock discovery;
- development/public-delay disclosure;
- radar status;
- product results when a valid snapshot is available;
- filters for game and availability where useful;
- retailer, product, NZD price, availability and observation time;
- external retailer link;
- accessible loading, no-results, stale and unavailable states.

The page must not imply that Gallant Peak is the seller for third-party retailer inventory. Retailer links remain clearly attributable to the retailer.

Supplier/retailer partnership language can be added separately, but no business is described as a partner until that relationship is confirmed.

## Failure behavior

Fail closed.

The website shows no current-stock claim when:
- fetch fails;
- JSON parsing fails;
- schema version is unsupported;
- required top-level fields are invalid;
- generated timestamp is invalid or too old;
- item availability is unknown/unrecognized;
- retailer URL is invalid or uses a disallowed protocol.

One bad item should be rejected without necessarily discarding an otherwise valid artifact, provided top-level integrity remains valid. The UI should report that some records were unavailable only if useful; it should not expose validation internals.

## Security boundary

No new browser-accessible route may reuse a trusted/admin bridge endpoint merely because it already exists. Public publication is a separate egress class with its own explicit schema and tests.

Existing bridge inventory/exclusion controls remain unchanged unless a separately reviewed TCG Hunt change requires them. The integration must not turn a previously excluded bridge path into an implicit public producer.

CORS, hosting and caching rules must be explicit for the public artifact. Only HTTPS retailer links are rendered as actionable external destinations.

No HTML from retailers is rendered through `dangerouslySetInnerHTML` or equivalent.

## Repository responsibilities

### `gallant-peak-tcg-hunt`

A later implementation plan should identify the exact module placement after current security prerequisites are reviewed. Conceptually it will add:
- a public snapshot schema/model;
- an allowlist serializer/publisher;
- publication delay/freshness policy;
- tests proving sensitive/internal fields cannot cross the public boundary;
- fixture(s) representing the public contract;
- deployment/publishing documentation.

### `gallant-peak-web`

Conceptually add:
- typed public snapshot model;
- runtime validation;
- fetch adapter with configurable public endpoint;
- TCG Hunt radar/result components;
- loading/error/stale/empty states;
- game/availability filtering if retained in implementation scope;
- tests for valid, malformed, stale and partially invalid snapshots;
- accessibility regression coverage;
- build/deployment configuration documentation.

## Test strategy

TCG Hunt tests should prove:
- only allowlisted fields are emitted;
- unsupported availability becomes non-publishable/unknown according to policy;
- timestamps and prices serialize deterministically;
- secrets/internal fields in source objects never appear in output;
- publication delay is enforced;
- malformed source observations fail closed;
- output conforms to schema v1.

Web tests should prove:
- valid fixture renders correct retailer/product/price/status/time;
- unknown availability never renders as in stock;
- stale snapshot produces the stale/unavailable state;
- unsupported schema produces unavailable state;
- malformed retailer URLs are not rendered as links;
- invalid individual records are rejected;
- fetch failure does not fall back to fake/demo stock;
- keyboard/focus/accessibility behavior remains intact;
- production build passes.

An integration/contract fixture should be shared or mechanically checked so the producer and consumer cannot silently drift.

## Deployment sequence

1. Complete/confirm prerequisite TCG Hunt security work before creating new public egress.
2. Implement and test the TCG Hunt public snapshot producer without exposing it publicly.
3. Generate a non-sensitive fixture and validate the web consumer against it.
4. Publish the public artifact to the selected HTTPS location.
5. Configure the Gallant Peak Web review deployment to consume it.
6. Verify stale/failure behavior deliberately.
7. Review the public output for sensitive-data leakage.
8. Only then describe the radar as connected on the public website.

## Non-goals for v1

- purchasing through TCG Hunt;
- marketplace checkout;
- customer accounts/watchlists;
- supplier order routing;
- direct access to collectors;
- real-time guarantees;
- exposing internal monitoring frequency;
- changing Discord alert behavior;
- automatically onboarding supplier APIs;
- changing Shopify product/fulfilment behavior.

## Future evolution

The same normalized ingestion boundary can later accept approved retailer/supplier feeds (API, Shopify, CSV/XML or manual partner tooling). Those inputs still pass through TCG Hunt normalization and publication policy before becoming public.

A versioned HTTP API can later replace the static snapshot for richer search, watchlists, geographic discovery and app clients. That transition should preserve the principle that the public contract is intentionally derived and less privileged than the internal monitoring model.

## Decision

Use TCG Hunt as the single stock-intelligence owner. Add a distinct, allowlist-built, delayed public snapshot boundary. Gallant Peak Web consumes that boundary and never communicates directly with collectors or trusted/admin bridge surfaces.
